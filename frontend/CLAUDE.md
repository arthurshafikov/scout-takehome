# Scout Frontend - Coding Conventions


## Component Conventions

### File Naming
- Components: `PascalCase.tsx` (e.g., `GalleryPage.tsx`)
- Utilities: `camelCase.ts` (e.g., `classColors.ts`)
- Slices: `camelCase.ts` (e.g., `filtersSlice.ts`)

### Component Structure
```typescript
// 1. Imports
import { FC } from 'react'
import { useAppDispatch, useAppSelector } from '@hooks/redux'

// 2. Types
interface GalleryPageProps {
  title: string
}

// 3. Component
const GalleryPage: FC<GalleryPageProps> = ({ title }) => {
  return <div>{title}</div>
}

// 4. Export
export default GalleryPage
```

### Hooks
- Use `useAppDispatch` and `useAppSelector` for Redux
- Use `useQuery` from RTK Query for API calls
- Custom hooks in `src/hooks/`

## TypeScript

### Strict Mode Enabled
- All types must be explicit
- No implicit `any`
- All functions must have return types

### API Types (Phase B)
```typescript
// src/types/api.ts
export interface Photo {
  id: string
  x: number
  y: number
  h: number
  width: number
  height: number
  capturedAt: string
  originalUrl: string
  predictions: Prediction[]
}

export interface Prediction {
  id: string
  photoId: string
  classId: string
  confidence: number
  bbox: BoundingBox
}

export interface BoundingBox {
  xMin: number
  yMin: number
  xMax: number
  yMax: number
}
```

## State Management

### Redux Slices
- Location: `src/features/{feature}/{featureSlice}.ts`
- Use RTK `createSlice` for reducers
- Actions auto-generated by RTK

### RTK Query
- API slice in `src/services/api.ts`
- Define endpoints with `createApi`
- Use tags for cache invalidation
- Separate queries from mutations

## Styling

### Tailwind CSS
- Use utility classes for all styling
- No custom CSS in components (exception: konva-specific styles)
- Tailwind config in `tailwind.config.js`

## Testing

### Test File Naming
- `Component.test.tsx` for React components
- `utils.test.ts` for utility functions
- Location: same directory as source file

### Test Setup
- Framework: Vitest
- Rendering: React Testing Library
- Config: `vitest.config.ts`

### Example Test
```typescript
import { describe, it, expect } from 'vitest'
import { render, screen } from '@testing-library/react'
import GalleryPage from './GalleryPage'

describe('GalleryPage', () => {
  it('renders title', () => {
    render(<GalleryPage title="Test" />)
    expect(screen.getByText('Test')).toBeInTheDocument()
  })
})
```

## API Integration

### Query Parameters
- All params snake_case (backend requirement)
- Cursor pagination: base64 JSON `{capturedAt, id}`
- Max limit: 200

### Response Format
```typescript
interface APIResponse<T> {
  success: boolean
  data: T
  error?: {
    code: string
    message: string
  }
  trace_id: string
}
```

### Thumbnail URLs
- Format: `http://localhost:8080/api/thumbnails/{photoId}`
- No need to fetch through RTK Query (browser caches blobs)
- Direct string URLs in image tags

## Build & Deploy

### Dev Server
```bash
npm run dev
# Server at http://localhost:5173
# API proxy: /api/* → http://localhost:8080
```

### Production Build
```bash
npm run build
# Output: dist/
```

### Docker
- Dockerfile: multi-stage build (Node → nginx)
- Nginx config: SPA fallback + /api/* proxy
- Port: 80 (exposed as 5173 in docker-compose for dev)
